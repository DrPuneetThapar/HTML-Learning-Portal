projects

Build real projects, not just examples

Three guided project briefs, one per difficulty tier, each combining concepts across Units 1–3. Build them in the Playground or in your own code editor, then check your work against the requirements and rubric below.

How to use these: each brief lists concrete, checkable requirements — treat it like a real assignment spec. Build the whole thing as a single HTML file with embedded CSS (or separate .html/.css files), then self-grade with the rubric before treating it as "done."
Beginner

Personal Bio Page

~2–3 hours

Build a single-page personal profile — the kind of page you'd link from a resume. This project only needs Unit 1, so it's a good first real build once you've finished the HTML fundamentals topics.

Requirements
  • A valid HTML5 document with correct <!DOCTYPE>, lang attribute, charset, and a descriptive <title>
  • One <h1> with your name, followed by a short intro paragraph
  • A profile photo (or placeholder image) with meaningful alt text and explicit width/height
  • An unordered list of at least 4 skills or interests
  • At least one internal link (to another section via an id) and one external link (opening in a new tab safely)
  • A mailto: link so visitors can email you
  • Correct use of <strong>/<em> somewhere in your intro text (not <b>/<i>)
  • A <table> or <dl> listing 3–4 facts (e.g. education, location, hobbies)

Intermediate

Café Landing Page with Contact Form

~5–7 hours

Build a small business landing page for a fictional café — semantic structure, an accessible contact form, and enough CSS to make it look like a real page, not a plain document.

Requirements
  • Semantic layout: <header> with a <nav>, <main> containing multiple <section>s (Menu, About, Contact), and a <footer>
  • The nav is a Flexbox row aligning a logo and links with justify-content
  • A menu section built as an accessible <table> (thead/tbody, scope on header cells) listing at least 5 items with prices
  • A contact form: labeled name, email (required, type="email"), and message fields, plus a submit button
  • Every form field styled with a :focus state (border-color or box-shadow change)
  • A consistent color palette using at least 3 CSS custom properties declared on :root
  • A responsive image (object-fit or CSS max-width) in the About section, with real alt text
  • At least one media query so the layout adapts on a narrow screen (e.g. nav or menu table)
  • A "Skip to main content" link as the first element in <body>

Advanced · Capstone

Responsive Portfolio Website

~10–15 hours

A multi-section personal portfolio site — the closest thing to a real freelance/job-ready build in this course. Draws on all three units: accessible semantic HTML, a validated form, and a fully responsive CSS layout with motion.

Requirements
  • Full semantic structure: header/nav, a hero section, a projects/work section, an about section, a contact section, footer
  • A CSS Grid-based project gallery (repeat(auto-fit, minmax(…))) showing at least 4 project cards
  • Each project card has a hover transition (transform and/or box-shadow) using the transition property
  • A contact form with at least 4 field types (e.g. text, email, select, textarea), each with proper labels and at least 2 validation attributes (required, pattern, minlength, etc.)
  • :valid/:invalid styling on at least one form field
  • A theme built entirely from CSS custom properties on :root (at least 4 variables: primary color, background, text color, spacing unit)
  • At least one @keyframes animation (e.g. a subtle fade-in or a loading indicator), respecting prefers-reduced-motion
  • Fully responsive: a mobile-first media query strategy with at least 2 breakpoints, tested by resizing the browser down to ~375px wide
  • Full keyboard accessibility: visible focus states, a skip link, and a logical tab order
  • Passes a basic accessibility check: every image has real alt text, every input has a label, heading levels are in logical order (no skipped levels)

Tips before you start

  • Sketch the page structure in plain HTML first, with zero CSS — get the semantics and content right before you style anything.
  • Build mobile-first: style the narrow layout first, then add a media query to enhance it for wider screens.
  • Come back to the tag reference and your unit study guides (Unit 1, Unit 2, Unit 3) whenever you forget an attribute or property name — that's exactly what they're for.
  • Test keyboard navigation by actually unplugging your mouse (or just using Tab) for a minute on whatever you build.
